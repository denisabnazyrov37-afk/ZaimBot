# Telegram Loan Bot — extended demo

Бот работает полностью внутри Telegram, без Mini App.

## Что добавлено

- отдельная кнопка `✅ Подтвердить личные данные` сразу после ввода ФИО, телефона, даты рождения и адреса;
- финальная кнопка `✅ Подтвердить и отправить заявку`;
- фиксация времени обоих подтверждений;
- журнал действий (`audit_log`);
- статусы: pending / approved / rejected / paid;
- фиксация времени одобрения и выдачи;
- команда администратора `/case_ID` для формирования технической выписки по заявке;
- отправка администратору анкеты и фотографий документов;
- SQLite.

## Команды администратора

- `/admin` — список заявок;
- `/approve_ID` — одобрить;
- `/reject_ID` — отклонить;
- `/paid_ID` — отметить фактическую выдачу;
- `/case_ID` — получить техническую выписку по заявке.

## Render

Build:
`pip install -r requirements.txt`

Start:
`python bot.py`

Environment Variables:
- `BOT_TOKEN`
- `ADMIN_IDS` — Telegram ID администратора, несколько через запятую.

## Важное про взыскание

Бот формирует технический журнал и фиксирует подтверждения пользователя, но это НЕ гарантирует юридическую силу договора или взыскание.

Для гражданского займа в РФ ГК РФ предусматривает письменную форму при сумме свыше 10 000 рублей; расписка или иной документ может подтверждать договор и передачу денег. Сам договор займа между гражданами считается заключённым с момента передачи денег. Электронная переписка и цифровые материалы могут иметь доказательственное значение, если позволяет установить их достоверность.

Перед реальной эксплуатацией отдельно проработайте:
- юридический текст договора;
- способ заключения/подписания электронного договора;
- подтверждение личности;
- фиксацию факта и назначения банковского перевода;
- согласия и обработку персональных данных;
- сроки хранения и удаление паспортных фото;
- разграничение доступа администратора;
- резервное копирование и шифрование;
- применимые требования законодательства к выдаче займов.

В текущей версии фотографии хранятся через Telegram `file_id`, а не скачиваются в SQLite. Для реального сервиса нужно отдельно проектировать защищённое хранилище и правила доступа.

Для разработки используйте тестовые данные, а не реальные паспорта.
